Kaname 設定ガイド（日本語）
============================

対象バージョン: 設定スキーマ 1 / Quickshell 0.3.0


1. 設定ファイルの場所
---------------------

通常は次の3ファイルを使用します。

  ~/.config/kaname/config.json
      形状、透明度、アニメーション、テーマ、モニター、プロファイル

  ~/.config/kaname/menus.json
      ユーザー定義メニュー、サブメニュー、コマンド、provider

  ~/.cache/matugen/kaname-colors.json
      matugenが生成し、Kanameが監視するテーマ色

flakeのHome Manager moduleを使う場合は、初期ファイルの手動コピーは不要です。

  imports = [ inputs.kaname.homeManagerModules.default ];
  programs.kaname.enable = true;

設定変更はprograms.kaname.settings、メニュー変更はprograms.kaname.menusへ記述します。
生成されたJSONはNix storeへのリンクなので、直接編集しないでください。

Home Managerを使わない場合は、初期ファイルを次のように配置できます。

  mkdir -p ~/.config/kaname
  cp config/default.json ~/.config/kaname/config.json
  cp config/menus.json ~/.config/kaname/menus.json
  cp matugen/kaname-colors.json.template ~/.config/kaname/

config.jsonとmenus.jsonは実行中に監視されます。正しいJSONへ保存すると、通常は
Quickshellの再起動なしで反映されます。JSONが壊れている場合は直前の有効な設定を
維持します。

環境変数で場所を変更できます。

  KANAME_CONFIG_FILE   config.json
  KANAME_MENUS_FILE    menus.json
  KANAME_THEME_FILE    生成済みテーマJSON
  KANAME_QML_DIR       kaname CLIが接続するQuickshell設定ディレクトリ
  KANAME_APPLICATION_HISTORY_FILE
                       最近使ったアプリの履歴JSON

KANAME_QML_DIRは通常変更不要です。Kanameを共通Quickshellへ組み込む場合だけ、
共有シェルのshell.qmlがあるディレクトリを指定します。

  KANAME_QML_DIR="$HOME/.config/quickshell/shared" kaname --applications


2. JSON記述上の注意
-------------------

・コメントは書けません。
・文字列とキーはダブルクォートで囲みます。
・最後の要素の後にはカンマを書きません。
・すべての設定ファイルで "schemaVersion": 1 が必要です。
・透明度は0.0（完全透明）から1.0（不透明）です。
・コマンドはシェル文字列ではなく、必ず引数配列で指定します。

検査例:

  jq empty ~/.config/kaname/config.json
  jq empty ~/.config/kaname/menus.json


3. config.json
--------------

完全な例:

  {
    "schemaVersion": 1,
    "geometry": {
      "width": 1100,
      "height": 900,
      "centerOffsetX": 0,
      "centerOffsetY": 0,
      "radius": 760,
      "startAngle": 180,
      "endAngle": 270,
      "visibleItems": 7,
      "itemWidth": 150,
      "itemHeight": 104
    },
    "opacity": {
      "master": 1.0,
      "background": 0.72,
      "overlay": 0.10,
      "item": 0.92,
      "inactive": 0.50,
      "guide": 0.32,
      "fan": 0.22,
      "text": 1.0,
      "image": 1.0
    },
    "behavior": {
      "closeOnFocusLoss": false,
      "animationMs": 180,
      "themeAnimationMs": 350,
      "reducedMotion": false,
      "cacheRadius": 1
    },
    "theme": { "preset": "matugen" },
    "display": { "screen": "" },
    "profiles": {}
  }


3.1 geometry

  width / height
      layer-shellウィンドウの幅と高さ。入力範囲はwidth 320～4096、height
      240～4096です。現在の右下レイアウトでは見切れ防止のため、実表示は最低
      1100×900になります。

  centerOffsetX / centerOffsetY
      仮想円の中心を画面右下からずらす量。負のXは左、正のYは下です。
      範囲は-1000～1000です。

  radius
      項目軌道の半径。入力範囲は80～2000です。重なり防止のため、実際には
      760以上か、項目寸法から求めた必要半径の大きい方が使われます。

  startAngle / endAngle
      扇の角度（度）。同梱設定は180～270です。表示範囲は最低75度に
      補正されます。

  visibleItems
      同時表示数。1～15。通常は奇数（5または7）が中央配置に向いています。

  itemWidth / itemHeight
      各項目の寸法。48～500px。


3.2 opacity

  master       UI全体
  item         通常項目
  inactive     非選択項目
  guide        円弧ガイド線
  fan          扇背景
  text         中央テキスト
  image        サムネイル

backgroundとoverlayはスキーマ互換用に残っています。現在の「完全に透明な
ウィンドウ」表示では全面背景を描かないため、視覚効果はありません。


3.3 behavior

  animationMs
      選択、回転、開閉の基本時間。0～2000ミリ秒。

  themeAnimationMs
      色変更の遷移時間。0～5000ミリ秒。

  reducedMotion
      trueなら主要アニメーション時間を0にします。

  cacheRadius
      表示範囲の外側で先読みする項目数。0～5。画像は非同期縮小デコードされ、
      Qtのメモリキャッシュを利用します。

  keyBindings.enterLevel
      選択項目の子階層へ進むキー。既定値は"Left"。葉項目は実行しません。

  keyBindings.backLevel
      親階層へ戻るキー。既定値は"Right"。

指定可能なキー名はLeft、Right、Up、Down、Backspace、Return、Enter、Escape、
Space、Tabです。"None"を指定すると、その操作の追加キーを無効化します。
同じキーを複数操作へ割り当てないでください。Backspaceの階層戻り、Enterの
確定、Escapeの全終了は従来どおり利用できます。

closeOnFocusLossは将来互換用の予約キーです。現在はフォーカス喪失で閉じません。


3.4 theme

  preset: "matugen" | "dark" | "neon" | "mono"

matugenの場合だけ、~/.cache/matugen/kaname-colors.jsonを監視します。それ以外は
内蔵固定テーマです。


3.5 display

  screen
      Niri/Quickshellの出力名。例: "eDP-1"、"DP-1"。空文字または未知の名前は
      Quickshellの既定出力へフォールバックします。

確認:

  niri msg outputs
  ./bin/kaname --applications --screen eDP-1

CLIの--screenはconfig.jsonより優先されます。


3.6 profiles

プロファイルは基本geometry/opacityの一部だけを上書きします。未指定値は基本設定へ
フォールバックします。geometryでは全キー、opacityではmaster、item、inactive、
image、fanを現在上書きできます。

  "profiles": {
    "my-wallpaper": {
      "geometry": {
        "visibleItems": 5,
        "itemWidth": 240,
        "itemHeight": 150,
        "radius": 840
      },
      "opacity": {
        "fan": 0.16,
        "inactive": 0.38
      }
    }
  }

使用:

  find ~/.wallpapers/image -type f | sed 's|^|img:|' |
    ./bin/kaname --dmenu --profile my-wallpaper

同梱プロファイルはapplications、preview、compactです。


3.7 applications

--applicationsの根階層に表示する分類、順序、アイコンを設定します。

  "applications": {
    "title": "Applications",
    "description": "{count} applications",
    "categories": [
      {
        "id": "browser",
        "label": "Browsers",
        "icon": "web-browser",
        "key": "b",
        "match": ["WebBrowser", "Network"]
      },
      {
        "id": "settings",
        "label": "Settings",
        "icon": "preferences-system",
        "key": "s",
        "match": ["Settings", "System", "HardwareSettings"]
      },
      {
        "id": "media",
        "label": "Media",
        "icon": "applications-multimedia",
        "key": "m",
        "children": [
          { "id": "music", "label": "Music", "icon": "multimedia-player",
            "key": "m", "match": ["Audio", "Music"] },
          { "id": "images", "label": "Images", "icon": "image-x-generic",
            "key": "i", "match": ["Graphics", "Photography"] },
          { "id": "videos", "label": "Videos", "icon": "video-x-generic",
            "key": "v", "match": ["Video", "VideoEditing", "TV"] }
        ]
      }
    ],
    "recent": {
      "id": "recent",
      "label": "Recently Used",
      "icon": "document-open-recent",
      "key": "r",
      "limit": 10
    },
    "fallback": {
      "id": "other",
      "label": "Other",
      "icon": "applications-other",
      "key": "o"
    },
    "all": {
      "id": "all",
      "label": "All Applications",
      "icon": "view-app-grid-symbolic",
      "key": "a"
    }
  }

titleは根階層の見出しです。descriptionは各分類の説明で、{count}が件数に
置換されます。categoriesは上から順に評価され、最初に一致した分類だけへ入ります。matchには
desktop entryのCategories値（WebBrowser、Settings、Audioなど）を書きます。
iconには現在のシステムアイコンテーマで利用できるアイコン名を指定します。
childrenには同じ分類形式を入れ子にでき、親分類には子分類とそのアプリが表示されます。
分類判定は末端のmatchに対して、設定に書かれた順序で行われます。

どのmatchにも一致しないアプリはfallbackへ入ります。全アプリはallにも表示され、
allが有効な場合は根階層の先頭項目として初期フォーカスされます。
fallbackまたはallへ "enabled": false を追加すると、その項目を非表示にできます。
categoriesの配列順が根階層での表示順になります。設定変更は次回
--applicationsを開いたときに反映されます。

同梱の初期設定は公開利用を想定して英語表記です。label、title、descriptionを
日本語や漢字へ変更しても分類処理には影響しません。


3.8 最近使ったアプリ

Kanameから起動したDesktop Entryを、重複なしの新しい順で表示します。同梱設定は
直近10件です。ほかのランチャー、Niriのキーバインド、ターミナルなどから起動した
アプリは記録されません。

  "recent": {
    "id": "recent",
    "label": "Recently Used",
    "icon": "document-open-recent",
    "key": "r",
    "limit": 10
  }

  enabled   falseならRecently Usedを非表示
  id        内部ID
  label     根階層に表示する名前
  icon      システムアイコンテーマのアイコン名
  key       根階層内のショートカット
  limit     表示・保存件数。1～100。既定値10

履歴の保存先:

  $XDG_STATE_HOME/kaname/application-usage.json

XDG_STATE_HOMEが未設定なら次を使います。

  ~/.local/state/kaname/application-usage.json

保存先はKANAME_APPLICATION_HISTORY_FILEで変更できます。履歴を初期化する場合は、
Kanameを所有するQuickshellを終了してから履歴ファイルを削除してください。存在しない
Desktop EntryはRecently Usedから自動的に除外して表示します。履歴ファイルの破損や
欠落があっても、アプリランチャーのほかの分類は引き続き利用できます。


4. menus.json
-------------

基本構造:

  {
    "schemaVersion": 1,
    "menus": {
      "main": {
        "label": "要",
        "items": []
      }
    }
  }

起動:

  ./bin/kaname --menu main


4.1 共通項目フィールド

  id              一意なID。省略時は自動生成
  type            項目種別
  label           表示名
  description     中央領域の説明
  icon            アイコンテーマ名
  image           絶対画像パス
  value           値
  keywords        検索語の文字列配列
  key             現在階層内のキーバインド
  disabled        trueなら選択不能
  workingDirectory コマンドの作業ディレクトリ

keyは現在の階層だけで有効です。Backspaceで親へ戻ります。Escapeは検索中なら
検索を解除し、通常時は現在の階層に関係なくランチャー全体を閉じます。


4.2 applications

XDGデスクトップエントリ一覧を開きます。

  {
    "id": "apps",
    "type": "applications",
    "label": "Applications",
    "icon": "view-app-grid-symbolic",
    "key": "a"
  }


4.3 command

シェルを介さず、実行ファイルと引数をそのまま渡します。

  {
    "id": "files",
    "type": "command",
    "label": "Files",
    "icon": "system-file-manager",
    "command": ["nautilus", "--new-window"]
  }

次の形式は使用できません。

  "command": "program --option | other-program"

パイプ、リダイレクト、環境変数展開が必要なら、内容を検証した専用スクリプトを作り、
そのスクリプトを配列で呼び出してください。


4.4 submenu

  {
    "id": "tools",
    "type": "submenu",
    "label": "Tools",
    "children": [
      {
        "id": "terminal",
        "type": "command",
        "label": "Terminal",
        "command": ["foot"]
      }
    ]
  }


4.5 provider

外部プログラムのstdoutを動的な子項目として読みます。commandは必ず配列です。

  {
    "id": "sessions",
    "type": "provider",
    "label": "Sessions",
    "command": ["list-sessions", "--json"],
    "inputFormat": "jsonl"
  }

inputFormat:

  lines
      1行を1項目として表示します。現在のlines項目は表示専用です。

  jsonl
      1行を1 JSONオブジェクトとして読みます。実行可能項目を返せます。

providerはEOFまで読み取った後に一括表示します。実行中はLoading、空ならNo results、
失敗時はstderr付きエラーを表示します。

providerが返すJSON Lines例:

  {"id":"term","type":"command","label":"Terminal","command":["foot"]}
  {"id":"files","type":"command","label":"Files","command":["nautilus"]}


5. dmenu JSON Lines
-------------------

  printf '%s\n' \
    '{"id":"one","label":"One","value":"1","keywords":["first"]}' \
    '{"id":"media","label":"Media","icon":"folder","children":[{"label":"Two","value":"2","image":"/tmp/two.webp"}]}' |
    ./bin/kaname --jsonl --output value --prompt Structured

利用可能なフィールド:

  id, label, description, icon, image, value, keywords, key, disabled, children

childrenは同じ項目形式の配列で、任意の深さにネストできます。childrenを持つ項目は
自動的にサブメニューになります。iconにはテーマアイコン名、絶対パス、file: URLを
指定できます。

--output:

  raw     最上位は入力された元のJSON行、子項目はその項目のJSON（既定）
  value   value
  id      id
  json    Kanameが保持するJSONオブジェクト

壊れた行は終了コード2になり、エラーはstderrだけへ出ます。


6. matugenテーマJSON
--------------------

必要キーはschemaVersion、background、primary、textです。他のキーは任意ですが、
テンプレートでは次を生成します。

  background, surface, surfaceContainer, primary, secondary, tertiary,
  outline, text, textMuted, error

色は"#RRGGBB"形式です。透明度はテーマJSONではなくconfig.jsonで管理します。
壊れたテーマへ更新された場合、Kanameは直前の有効テーマを維持します。

matugenテンプレートは次の場所へ配置します。

  ~/.config/kaname/kaname-colors.json.template

リポジトリ同梱版を使う場合:

  mkdir -p ~/.config/kaname
  cp matugen/kaname-colors.json.template \
    ~/.config/kaname/kaname-colors.json.template

完全なテンプレート例:

  {
    "schemaVersion": 1,
    "background": "{{colors.background.default.hex}}",
    "surface": "{{colors.surface.default.hex}}",
    "surfaceContainer": "{{colors.surface_container.default.hex}}",
    "primary": "{{colors.primary.default.hex}}",
    "secondary": "{{colors.secondary.default.hex}}",
    "tertiary": "{{colors.tertiary.default.hex}}",
    "outline": "{{colors.outline.default.hex}}",
    "text": "{{colors.on_background.default.hex}}",
    "textMuted": "{{colors.on_surface_variant.default.hex}}",
    "error": "{{colors.error.default.hex}}"
  }

最小構成ではschemaVersion、background、primary、textだけでも動作します。
省略した色には、Kanameが現在保持している色または内蔵色が使われます。

  {
    "schemaVersion": 1,
    "background": "{{colors.background.default.hex}}",
    "primary": "{{colors.primary.default.hex}}",
    "text": "{{colors.on_background.default.hex}}"
  }

連携用apply-wallpaper.shは、このテンプレートをmatugenへ渡し、生成結果を次へ
アトミックに配置します。

  ~/.cache/matugen/kaname-colors.json

Kanameは生成先を監視しているため、正常なJSONへ置き換わるとQuickshellを再起動せず
色を更新します。テンプレートまたは生成先を変更する場合は、それぞれ次の環境変数を
使用します。

  KANAME_TEMPLATE=/path/to/template.json
  KANAME_THEME_FILE=/path/to/generated-colors.json

KANAME_THEME_FILEはapply-wallpaper.shと、Kanameを起動するQuickshellプロセスの
両方へ同じ値を渡してください。テンプレートが存在しない場合は新しいKaname用JSONを
生成せず、既存JSONがあればその色を維持し、なければKaname内蔵色を使用します。


7. 優先順位とトラブルシューティング
-------------------------------------

値の優先順位:

  CLIオプション > 指定プロファイル > config.json基本値 > QML内蔵値

設定を反映できない場合:

  1. jq emptyでJSONを検査する
  2. 開発ツリーでは次のコマンドでログを確認する

     quickshell log -p "$PWD/quickshell" -t 100

     Nixパッケージではkaname-shellを起動しているsystemdユーザーサービスの
     journalも確認する

     journalctl --user -u kaname.service -b
  3. 必要ならQuickshellを再起動する

  quickshell kill -p "$PWD/quickshell"
  quickshell -p "$PWD/quickshell" --daemonize
